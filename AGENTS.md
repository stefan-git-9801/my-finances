# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

`my-finances` – a private hobby finance web app. One deployable unit: the .NET API
serves both `/api/*` and the built React SPA from `wwwroot/` (same origin, no CORS).

- **Frontend** (`web/`): React + Vite + TypeScript, Fluent UI v9, TanStack Router
  (file-based) + TanStack Query. API client is **generated by Orval** – never edited by hand.
- **Backend** (`backend/`): .NET 10, **Minimal API** (not MVC controllers), EF Core + Npgsql.
  Solution file is `backend/Backend.slnx` (new XML format).
  - `MyFinances.Api` – endpoints, auth, `Program.cs`; `BalanceService` (derived account
    balances), `RecurringMaterializer` (turns recurring templates into bookings; runs at
    startup and via an endpoint filter before `transactions`/`dashboard`/`reports` GETs)
  - `MyFinances.Data` – `AppDbContext`, entities, **EF migrations live here**; also two pure
    helpers with tests: `Recurring/RecurringSchedule` and `Csv/CsvWriter`
  - `MyFinances.Data.Tests` – xUnit

- **Domain**: single-user Haushaltsbuch. Entities: `Account` (type + starting balance),
  `Category` (kind + optional monthly budget), `Transaction` (income/expense, positive amount,
  required category, optional note), `Transfer` (between two own accounts – counts towards
  balances, excluded from income/expense reports), `RecurringTemplate` (monthly, fixed day).
  EUR only. Deutsche UI throughout.
- **DB**: PostgreSQL. Local = Podman container. Prod = Neon (free tier).
- **Hosting**: Railway, builds `backend/Dockerfile` (config in `railway.json`).

## Commands

```bash
# Local database
podman compose up -d db adminer          # needs `brew install docker-compose` as provider

# Backend (migrates + seeds on startup in Development)
dotnet run --project backend/src/MyFinances.Api        # http://localhost:5023
dotnet test backend/Backend.slnx

# Frontend
cd web && pnpm install && pnpm dev                      # http://localhost:5173 (proxies /api)
pnpm build                                              # tsr generate + tsc + vite
pnpm lint

# Full container stack (as in prod)
podman compose up --build                               # http://localhost:8080

# EF migrations
dotnet ef migrations add <Name> \
  --project backend/src/MyFinances.Data \
  --startup-project backend/src/MyFinances.Api
```

## The API-client workflow (important)

The OpenAPI document is generated at **build time** into `backend/openapi/MyFinances.Api.json`
and committed. Orval reads that file. After **any** change to endpoints or DTOs:

```bash
dotnet build backend/src/MyFinances.Api    # regenerates backend/openapi/MyFinances.Api.json
cd web && pnpm generate                     # regenerates web/src/api/generated/
```

Commit both. CI (`.github/workflows/ci.yml`) fails if they are stale (`git diff --exit-code`).

## Conventions

- **Minimal API only.** Endpoints as `static` methods grouped per feature in
  `backend/src/MyFinances.Api/Features/<Area>/<Area>Endpoints.cs`, registered via a
  `Map<Area>Endpoints(this IEndpointRouteBuilder)` extension called from `Program.cs`.
  Give every endpoint `.WithName("…")` – that becomes the Orval hook name.
- Return `TypedResults` / `Results<...>` unions so OpenAPI response types are accurate.
- DTOs are `record`s in `<Area>Dtos.cs` with a `ToResponse()` mapping extension.
  Never expose EF entities directly.
- Validation via `MiniValidation` (`MiniValidator.TryValidate`) + DataAnnotations on DTOs.
- Frontend: functional components, hooks from `web/src/api/generated/**`, Fluent UI
  components + `makeStyles`. Route files under `web/src/routes/`.
- C#: 4-space indent, `Nullable` enabled. TS/TSX: 2-space, Prettier (`web/.prettierrc.json`),
  no semicolons, single quotes.

## Gotchas

- **pnpm is pinned** to `10.10.0` (`packageManager` field). Don't bump casually – pnpm 11
  breaks `pnpm.onlyBuiltDependencies` in `package.json` and the frozen-lockfile install.
- `web/src/routeTree.gen.ts` is generated (git-ignored); `pnpm build`/`pnpm dev` create it.
- Auth is **cookie-based, same-origin**. The Axios mutator sets `withCredentials: true`.
  API returns `401`/`403` for `/api/*` instead of redirecting.
- **No registration endpoint.** The single user is seeded from `ADMIN_EMAIL` / `ADMIN_PASSWORD`
  on startup (`DbSeeder.SeedAdminUserAsync`). Don't add a `/register` route back.
- **EF `GroupBy` can't project a navigation property into the key** on Npgsql – group by the FK
  id, then look up related names in a second query (see `ReportsEndpoints.ExpensesByCategory`).
- `Program.cs` skips the startup migration when loaded by the build-time OpenAPI tool
  (`GetDocument.Insider`) – keep that guard if you touch startup code.
- Connection string accepts **either** a native Npgsql string **or** a `postgres://` URL
  (Neon/Railway form) – `DatabaseConnectionString.Normalize` converts it.
- Config keys: `ConnectionStrings__AppDb` (or `DATABASE_URL`), `RUN_MIGRATIONS_ON_STARTUP`,
  `PORT` (host-provided), `ASPNETCORE_ENVIRONMENT`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
- Two `dotnet` builds of the API project at once (e.g. an agent building while `dotnet run`
  is up) corrupt `obj/` – symptom: `Failed to read '…/obj\Debug/…/staticwebassets.development.json'`.
  Fix: stop all `dotnet` processes, `rm -rf backend/src/*/obj backend/src/*/bin`, rebuild once.
- `RelationalEventId.ConnectionError` is downgraded to Debug in `Program.cs` – `MigrateAsync()`
  logs it at Error on the first start (DB doesn't exist yet); real outages still surface as
  the failing request's exception + 500.

## Don't

- Don't edit anything under `web/src/api/generated/` or `backend/openapi/` by hand.
- Don't add MVC controllers.
- Don't commit `.env`, secrets, or real connection strings. Use `dotnet user-secrets`
  locally and Railway variables in prod.
- Don't switch the local stack to Docker – this project uses Podman.
